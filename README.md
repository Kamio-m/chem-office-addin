# 化学工具 · Office 加载项
可以加载进入word，ppt，excel（暂定）
## 一、直接使用：双击 `化学工具.exe`

项目根目录下的 **`化学工具.exe`**（约 83 MB）是打包好的单文件程序，
**内嵌了前端、清单和 https 证书，不依赖 Node、不依赖 npm**。
双击 → 出现一个黑色窗口 → 它会自动完成三件事：
1. 在本地启动 https 服务 `https://localhost:3000`
2. 把加载项注册到当前用户的 Office
3. 列出菜单，可以直接按数字打开 Word / Excel / PowerPoint
然后在这些程序里找到它：

> **插入 → 我的加载项 → 共享文件夹 / 开发人员加载项 → 化学工具**

**这个窗口要一直开着**（它就是服务本身），关掉窗口加载项就打不开了。

窗口里的按键：

| 键 | 作用 |
| --- | --- |
| `1` / `2` / `3` | 打开 Word / Excel / PowerPoint |
| `4` | 浏览器预览界面（不用装 Office 也能先看看） |
| `5` | 重新注册到 Office（换机器或注册掉了时用） |
| `6` | 从 Office 注销 |
| `Q` | 退出并停止服务 |

> **首次运行如果弹出「Windows 已保护你的电脑」**：点 **更多信息 → 仍要运行**。
> 这是因为 exe 没有代码签名（打包过程会破坏原 Node 的签名），并非病毒。
>
> **若提示证书不安全**：窗口会自动尝试把证书加入「受信任的根证书颁发机构」，
> 弹确认框时点「是」即可；也可以手动双击 `%LOCALAPPDATA%\ChemOfficeAddin\localhost.crt` 安装。

### 重新打包 exe

```bash
npm run exe     # 等价于 node launcher/build.mjs
```

它会先构建前端，再用 Node SEA 把 `launcher/server.cjs` + `dist/` + `manifest.xml` + 证书
注入到 `node.exe` 里，输出 `化学工具.exe`。

## 二、开发模式（改代码用）

需要本机有 Node 18+（当前这台机器上 Node 在 WorkBuddy 目录内，未加入系统 PATH，
所以直接开 cmd 敲 `npm` 会提示找不到命令，需要先把它的目录加进 PATH）。

```bash
cd chem-office-addin
npm install
npm run certs        # 生成并信任 https://localhost 开发证书（仅首次）
npm run dev          # https://localhost:3000
```

另开一个终端注册加载项（**Office 需先关闭**）：

```bash
npm run sideload     # 注册到当前用户，之后打开 Office 即可在「我的加载项」里看到
```

打开 Word / Excel / PowerPoint → **插入 → 我的加载项 → 共享文件夹 / 开发人员加载项 → 化学工具**。

> 也可以直接 `npm run open:word` / `open:excel` / `open:ppt`，会带着加载项一起启动对应的 Office 程序。

调试期间只要 `npm run dev` 在跑，改动代码会自动热更新到任务窗格。
不再需要时执行 `npm run unload` 注销。

只想调试启动器本身（不打包）：`npm run dev:launcher`，它会直接读 `dist/` 目录。

### 找不到加载项？

| 现象 | 处理 |
| --- | --- |
| 「我的加载项」里没有 | 确认 `npm run sideload` 成功、Office 已重启；`office-addin-dev-settings registered` 可查看已注册列表 |
| 打开是白屏 | 任务窗格里右键 → 重新加载；确认 `https://localhost:3000` 能在浏览器打开且证书受信任 |
| 提示证书不安全 | 重新执行 `npm run certs`，或在「证书管理器 → 受信任的根证书颁发机构」中确认 `Developer CA for Microsoft Office Add-ins` |
| 端口被占用 | 改 `vite.config.ts` 里的 `port`，同时改 `manifest.xml` 中所有 `https://localhost:3000` |
| Excel 里看不到按钮 | Excel 的加载项入口同样是「插入 → 我的加载项」，不在功能区 |

## 二·附：化学式写法

输入框里用**接近手写习惯**的语法，右侧实时预览，点「插入」即落到光标位置。

### 输入联想

打字时会在光标下方弹出补全列表。**联想 = PubChem 在线（只保留无机物）+ 本地离子表**，有机物、药物、公司名一律滤过：

| 你打 | 联想内容 |
| --- | --- |
| `H2S` | 在线：H₂SiO₃、H₂Se、H₂SO₄、H₂S₂（全是无机） |
| `NaO` | 在线：NaOCl 次氯酸钠、NaOH 氢氧化钠（反查兜底救回） |
| `KMnO` | 在线：KMnO₄ 高锰酸钾 |
| `co` | 本地离子：CO₃²⁻（PubChem 对 ≤2 字符前缀返回空，见下方说明） |
| `Fe` | 本地离子：Fe²⁺、Fe³⁺ |
| `KNOLL` / `CON` | 空（公司名、有机物全部滤过） |

```
输入 → PubChem autocomplete → 抽化学式 → 三道过滤 → 结果
  ① 所有元素 token 必须是真实元素符号（KNOLL 的 L 不是元素 → 滤）
  ② 含 C 又含 H 视为有机物 → 滤（碳酸盐/氰/硫氰酸盐例外，仍属无机）
  ③ 无机物才放行
名字没带「(化学式)」的条目 → 并发反查 PubChem 拿分子式 → 再走一遍过滤
```

- 左侧小圆点：灰=未触发、蓝闪=查询中、绿=在线可用、橙=失败已回落
- **本地只保留离子表**（Fe²⁺、SO₄²⁻、NO₃⁻、MnO₄⁻…），化合物/元素条目已删除
- **PubChem 的硬限制**：autocomplete 对 ≤2 字符的前缀一律返回空，所以 `co`、`Na`、`Fe`
  拿不到在线结果，只剩匹配到的本地离子；3 个字符起才正常
- 在线超时 2.5 秒或失败时静默回落，不打断输入
- `=[` 反应条件联想：点燃、加热、高温、催化剂、通电、光照、浓硫酸…
- 空输入时列出**最近使用过**的公式（localStorage，最多 8 条）
- 方程式（反应式）不走联想联想，需要时用「常用模板」按钮或 `=[]` 条件写法手打
bChem）

输入**化学式前缀**（大写字母开头，可带数字）时，会去 PubChem 查同前缀的化学式：

```
输入 H2S  →  在线 H2SiO3   Silicic acid
              在线 H2Se
              在线 H2SO4    硫酸          ← 中文名来自本地库
              在线 H2S2     Hydrogen sulfide
```

实现方式：PubChem 的 `autocomplete/compound` 返回的是「名字 + 化学式」混排的模糊匹配，
我们在服务端用正则把**化学式抽出来**，再按用户输入的前缀严格过滤，所以列表里只有化学式、没有英文化合物名。

- 左侧小圆点表示状态：灰=未触发、蓝闪=查询中、绿=在线可用、橙=在线失败已回落
- **元素符号不查在线**（输入 `Fe` 直接给本地化学式，不会被 Fentanyl 之类挤掉）
- 超时 2.5 秒或失败时**静默回落到本地库**
- 同一条化学式若本地有中文名，会用它作为提示，并去掉重复项


**为什么要有本地代理**：浏览器直接 fetch PubChem 会被 CORS 拦住（对方没有放开跨域）。
所以请求先到本地服务的 `/api/chem/suggest`，由 Node 侧转发，顺带做 10 分钟缓存。

> 开发态由 `vite.config.ts` 里的 `pubchemDevProxy` 插件提供同一端点，
> 生产态由 `launcher/server.cjs` 提供（那边是 SEA 单文件，代码只能内联，所以两处各有一份等价实现）。

**关于 ORD**：Open Reaction Database 并没有公开可查的 REST 接口，`ord-interface`
是需要自行托管的 FastAPI + PostgreSQL + RDKit 服务，且内容是文献里的有机反应，
不含中学方程式。所以在线源选了 PubChem。

其他输入细节：

- 输入框随内容自动增高（最多 200px）
- 括号不配对时下方会给出提示
- 实时预览与「插入」用的是同一套排版结果，所见即所得

### 语法

| 输入 | 效果 | 说明 |
| --- | --- | --- |
| `H2SO4` | H₂SO₄ | 元素符号、右括号后的数字自动变下标 |
| `HCL` / `NAOH` / `CUO` | HCl / NaOH / CuO | **大小写自动规范化**（按元素表重建，`CO`、`SO` 仍按 C+O、S+O 拆读） |
| `Ca(OH)2` | Ca(OH)₂ | |
| `CuSO4·5H2O` | CuSO₄·5H₂O | `·` 后的系数保持正常大小 |
| `Fe^3+` | Fe³⁺ | `^` 表示上标电荷 |
| `SO4^2-` | SO₄²⁻ | 上下标可同时存在 |
| `H_{2}O` / `x^{n}` | | 花括号显式指定上下标内容 |
| `2H2 + O2 =[点燃] 2H2O` | 2H₂ + O₂ ═(点燃) 2H₂O | **无机反应用等号**，`[]` 内为上方条件 |
| `2H2 + O2 =[点燃\|催化剂] 2H2O` | 等号上方「点燃」、下方「催化剂」 | `\|` 前为上、后为下 |
| `CH4 + 2O2 ->[点燃] CO2 + 2H2O` | CH₄ + 2O₂ →(点燃) CO₂ + 2H₂O | **有机反应用箭头** |
| `<=>[高温高压\|催化剂]` | ⇌ 上方高温高压、下方催化剂 | `\|` 分隔上/下条件 |
| `<-` / `<->` / `=>` | ← / ⇄ / → | 其它箭头 |
| `↑` `↓` `Δ` `·` | | 直接输入即可 |

> **等号还是箭头**：按中学规范，无机反应用等号 `=`（也支持 `=[]` 带条件写法），有机反应用箭头 `->`。
> 手打方程式时按此规范书写；「常用模板」里的示例同样遵循。

**大小写自动规范化**：输入框里保持你敲的原样，但预览与插入的都是规范写法——字母段按元素表重建成
`HCl`、`NaOH`、`CaCO3`、`KMnO4` 这种大小写。已经写对的（`NaCl`、`Ca(OH)2`）不动；
括号里的物态符号 `(s) (l) (g) (aq)`、`[ ]` 里的反应条件（如 `hv`）、`n-` 这类前缀一律原样保留。
两可的写法按中学常见读法：`CO`→C+O（一氧化碳）、`SO`→S+O、`HF`→H+F，而 `CU`→Cu、`SI`→Si、`SN`→Sn。

**上下条件不用手打 `|`**：点工具栏的 `=[]` 按钮（光标落入方括号后），输入框下方会自动出现
「反应条件」面板——「上」「下」两行分别填，**边输入边生效**，两行都清空即去掉条件；
光标移出 `[]` 面板自动收起。光标点进已有条件时会自动带出当前值，改完直接改原文。
写错了按 `Ctrl+Z` 撤销。

**联想什么时候消失**：按 `Esc`、点输入框外面、或按 `Tab` 选中一条之后，列表都会立刻收起，
并且不会自己再弹回来（要等你继续打字）。与已输入完全相同的式子不再出现在列表里。

工具栏上的符号按钮会把字符插到光标处。多行输入会渲染成多行公式一起插入。
输入内容自动存草稿，**按文档隔离**：同一份文档里切换页签、关掉面板、刷新都还在；
换一份新文档则从空白开始（结构式是空画布，化学式是空输入框）。

草稿键形如 `chem-addin.formula-draft:<文档 id>` / `chem-addin.ket-draft:<文档 id>`，
文档 id 优先取 `Office.context.document.settings`（随文档保存），拿不到时退回文档 URL 映射，
再拿不到才临时生成一个（浏览器预览用固定值 `standalone`，方便调试）。
早期版本的全局草稿只会在打开**已保存的文档**时迁移过去一次，不会灌进新建的空白文档。

## 三、安装与更新

### 安装（推荐：安装包）

双击 `installer/化学工具安装包.exe`（29MB，普通用户权限即可，不需要管理员）：

- 装到 `%LOCALAPPDATA%\ChemOfficeAddin\`（exe + manifest + 托盘脚本）
- 自动注册 Office 加载项（HKCU 的 WEF 开发者项），并清理旧版共享文件夹注册项
- 勾选「开机自动启动」后写入 HKCU Run 项：开机自动进托盘、服务随托盘拉起
- 安装完直接启动托盘；控制面板可卸载

### 任务栏托盘（手动启停服务）

装好后双击桌面「化学工具」→ 任务栏右下角出现图标（无窗口）。右键菜单：

| 菜单项 | 作用 |
| --- | --- |
| 打开工具面板 | 浏览器打开 `https://localhost:3000`（排查用） |
| 启动服务 | 拉后台服务（`化学工具.exe --silent`） |
| **停止服务** | 结束 `化学工具.exe`，端口 3000 关闭，Word 面板随即不可用 |
| 重启服务 | 先停再起，改完配置或卡住时用 |
| 开机自动启动 | 勾选状态即当前是否随系统启动（写 HKCU Run） |
| 退出托盘 | 只关掉托盘图标，服务照旧运行 |

- 图标悬停显示「化学工具 · 运行中 / 已停止」，双击图标直接开面板
- 单实例：重复双击不会出现两个图标
- 卸载后托盘会自动退出（检测到程序文件被删）
- 想"全部关停"：先「停止服务」，再「退出托盘」

> **安装卡在「Closing applications...」**：旧的化学工具服务还在运行。
> 新版本安装包会在安装前自动结束该进程；若仍卡住，先在任务管理器结束「化学工具」，
> 点 Cancel 后重新运行安装包。
>
> **装完后 Word 里没有「化学工具」组**：关闭 Word，在安装目录
> （%LOCALAPPDATA%\ChemOfficeAddin）右键 `修复加载项.ps1` → 使用 PowerShell 运行，
> 它会重新注册加载项并拉起服务，再重开 Word 即可。

**装好后**：重启 Word / Excel / PowerPoint → 「开始」选项卡右侧出现 **化学工具** 组
→ 点「打开工具窗」按钮，右侧弹出任务窗格（形态同 GPT for MS Word）。

> 首次使用若 Word 提示"此加载项来自不受信任的来源"，在
> 文件 → 选项 → 信任中心 → 信任中心设置 → 加载项 里勾选允许即可。

## 四、三端插入方式

同一个任务窗格会根据宿主自动给出不同的插入选项：

| 宿主 | 可编辑公式 (OMML) | 图片 | 纯文本 | 默认 |
| --- | --- | --- | --- | --- |
| **Word** | ✅ 推荐，Word 原生公式，可在文档里继续编辑、随正文字号缩放 | ✅ | ✅ | 可编辑公式 |
| **Excel** | ✕（Excel 不支持 OMML） | ✅ 浮动图片 | ✅ 单元格内 Unicode 上下标 | 纯文本 |
| **PowerPoint** | ✕ | ✅ 需 PowerPointApi 1.8+ | ✅ 文本框 | 图片 |

说明：

- **Word 可编辑公式**用 `Range.insertOoxml` 插入 Flat OPC 包，公式体为 `m:oMath`，
  元素符号使用直立（`m:sty = p`）排版，符合化学式书写规范；反应条件用 `m:limUpp / m:limLow` 叠在箭头上下方。
  若插入失败会自动降级为图片，不会让操作失败。
- **PowerPoint 没有 `shapes.addPicture`**，官方替代做法是「矩形 + `shape.fill.setImage()` + 隐藏边框」，需要 PowerPointApi 1.8；
  旧版本会自动降级成文本框 + Unicode 上下标。
- **PPT 的位置**：PowerPoint 的图片永远是浮动形状，Office.js 也没有「光标坐标」接口，所以无法真正跟随
  I 形光标。现在的做法是以**当前正在编辑的文本框**为锚点，落在它的左下角下方一点（PowerPointApi 1.5 的
  `getSelectedShapes`）；没有选中任何形状时放在幻灯片中央，而不是像以前那样钉死在左上角。
- **图片**统一按 3 倍分辨率栅格化（公式由 SVG 渲染，缩放不糊）。
- **公式图片的插入大小**由「字号 × 插入大小」决定：面板里 `字号` 控制排版基准（同时影响预览），
  下方 `插入大小 小/中/大`（0.5 / 0.75 / 1）再等比缩放；100% 时按字号的自然尺寸，
  任何情况下都不会超过版心宽度（以前会强行拉满版心，导致插进去特别大）。
  结构式图片按**内容自身大小**插入（一个苯环约 2~3 cm），只有内容本身很宽时才会缩到版心宽度；
  早先那版是直接拉满版心，单个环会占满整页。

## 五、结构式（Ketcher）

「结构式」页签内嵌了 **[Ketcher](https://github.com/epam/ketcher)**（EPAM 开源的专业结构式编辑器），
由 **Indigo WASM** 在浏览器本地计算，**完全离线**，不依赖任何渲染服务。

能做的事：

- 单键 / 双键 / 三键、链状与环状结构、稠环
- 元素周期表、电荷、同位素、原子标签
- 立体化学（楔形键 / 虚线键）、R 基团、S 基团、聚合物
- 模板库、SMILES / MOL 导入导出
- 撤销 / 重做 / 框选 / 旋转 / 缩放

画完点「插入结构式」，会：

1. 用 `getSmiles()` 取当前结构
2. 用 `generateImage(smiles, { outputFormat: 'png' })` 交给 Indigo 渲染成白底 PNG
3. 按最大 320px 宽等比缩放后插入文档

「示例」可一键载入苯环试用；「清空」重置画布。

### 图片识别（在线 · OSRA）

点「图片识别」选一张结构式图片，识别结果以 **MDL MOL** 加载进 Ketcher——

> 落下来的是**真正的分子结构**，不是贴图。可以直接选中原子改元素、加键/删键、
> 补基团、调整立体化学，改完再点「插入结构式」。这一点和贴图有本质区别。

链路：

```
选图 → 前端缩到 ≤1600px → POST /api/ocr-online（本地服务转发，避开 CORS）
     → 上传到 NCI 的 OSRA 服务（带随机 fid）
     → 轮询 /tmp/osra-<fid>/done 拿结构数
     → 读 ctab.0（MOL，行分隔符是 '|'）
     → 还原成标准 MOL → ketcher.setMolecule()
```

- 引擎是 **[OSRA](https://sourceforge.net/projects/osra/)**（美国国立癌症研究所 NCI 出品，
  2007 年起，GPLv2），跑在它的官方在线服务 `cactus.nci.nih.gov` 上
- **不占本地体积**，安装包仍是 113 MB
- 需要联网，图片会上传到 NCI 服务器
- 输出是 MOL 而不是 SMILES——对 Ketcher 更友好，不用再做格式转换

**实测结果（3 次，PubChem 标准结构图，全部正确）**：

| 分子 | 识别出的骨架 | 真实骨架 | 判定 |
| --- | --- | --- | --- |
| 阿司匹林 | 9C + 4O + 1H | C9O4 | ✅ |
| 咖啡因 | 8C + 4N + 2O | C8N4O2 | ✅ |
| 布洛芬 | 13C + 2O + 1H | C13O2 | ✅ |

**杂原子一个没丢**——这点比 DECIMER 强：同样的三张图，DECIMER 是 6 次 3 对，咖啡因丢了一个羰基。

**为什么选它**：Imago（7 MB）、MolVec（1.2 MB）这两个本地传统算法实测对矢量渲染图
全错（连阿司匹林的 4 个氧都认不出）；MolScribe 最准但要 1.1 GB。OSRA 是唯一
「免费 + 准确 + 零体积」的组合。

**注意**：OSRA 的 Windows 二进制是**收费**的（官方下载页写明 purchase），
源码编译要凑 GraphicsMagick / OpenBabel / Potrace / patched GOCR / OCRAD / TCLAP
六个依赖，所以这里走的是官方在线服务，不是本地引擎。

**分辨率仍然重要**：图片越清晰越准，前端只缩小、不放大——实测插值放大不产生新信息。

### 关于体积

Ketcher + Indigo WASM 打包后约 **29 MB**（gzip 8.5 MB），因此：

- 单独分包、**点开「结构式」页签时才加载**，化学式页签不受影响
- exe 体积从 83 MB 增至 **113 MB**
- 首次打开该页签需要几秒初始化 WASM，界面会显示加载提示

### 构建上的两个坑

1. **`process is not defined`**：Ketcher 的依赖里残留 Node 的 `process`/`global` 引用。
   `index.html` 里在模块脚本之前注入了一个最小 `window.process` 垫片。
2. **`require is not defined`**：依赖混用了 ESM/CJS，只在生产构建里暴露。
   需要 `build.commonjsOptions.transformMixedEsModules: true`。

### exe 是怎么打出来的

用 Node 22 的 **SEA（Single Executable Application）**：把启动脚本、`dist/` 里的前端资源、
`manifest.xml`、https 证书全部塞进一份 blob，注入到 `node.exe` 的副本里。
所以 exe 体积 ≈ Node 运行时（84 MB），换来的是**目标机器什么都不用装**。

注册加载项写的是 `HKCU\SOFTWARE\Microsoft\Office\16.0\Wef\Developer`，
值名是清单里的 `Id`（GUID）、数据是清单路径 —— 与 `office-addin-dev-settings` 完全一致，
只是不依赖 npm 工具链。若 `reg.exe` 被安全策略拦住，会自动退回 PowerShell 的注册表提供程序。

### 排版引擎为什么自己写

化学式不是普通富文本：下标要跟随基线、上下标可能同时出现、箭头要能把条件叠在上方且宽度自适应。
`src/lib/svg.ts` 用 canvas 测宽 + 逐 token 排版生成 SVG，同一份排版结果同时用于**预览**和**位图导出**，
保证所见即所得；`src/lib/omml.ts` 再把同一份 token 流映射成 Word 公式结构。

## 七、部署到内网 / 正式环境

1. `npm run build` 生成 `dist/`；
2. 把 `dist/` 部署到内网 https 站点，例如 `https://addin.example.com/`；
3. 复制 `manifest.xml`，把其中所有 `https://localhost:3000` 替换为上面的域名；
4. 通过 Microsoft 365 管理中心「集成应用 → 上载自定义应用」分发清单，或继续用共享文件夹目录分发。

`manifest.xml` 的 `Id` 保持不变，升级时覆盖同一清单即可。

## 八、已验证 / 已知限制

- ✅ OMML 结构经 Word 实际打开校验：`2H₂ + O₂ —点燃→ 2H₂O`、`Fe³⁺ + 3OH⁻ → Fe(OH)₃↓` 均被识别为原生公式（`OMaths.Count = 2`）。
- ⚠️ Word 的行内公式用 `insertOoxml` 的 `replace` 位置插入，会替换当前选区，插入前请把光标放到目标位置。
- ⚠️ Excel 单元格里是 Unicode 上下标（`H₂SO₄`），能参与检索但**不是**真正的富文本格式。
- ⚠️ PowerPoint 图片插入依赖 PowerPointApi 1.8（Microsoft 365 / Office 2021 及以上）。
- ⚠️ 结构绘制的吸附是在自由绘制基础上做的近似晶格，复杂立体结构（椅式构象、楔形键）建议仍用专业软件作图后走「图片导入」。
- ⚠️ 图片识别走 NCI 的在线 OSRA 服务，需要联网、图片会上传。实测三个分子全对，但任何 OCR 都可能出错，识别后仍建议核对一遍再插入。
